# v0.3.5 — Product Flavor Profile Registry, batch 2

## Цель

Второй приоритетный батч Product Flavor Profile Registry (см. общее назначение и модель в `docs/engine-changelog/v0.3.5-product-flavor-profile-registry.md` и `docs/architecture/product-flavor-profile-registry.md`). Покрытие расширено с 15 до 30 из 86 `RESOLVED` канонических продуктов. Registry по-прежнему не подключён к `calculateMixAnalysis`, scoring или UI.

## Очередь приоритизации

Ранги 16–30 той же детерминированной очереди `verifiedMixCount → componentOccurrenceCount → occurrenceCount` (по убыванию), что использовалась для batch 1 и для P0/P1 identity decisions. Batch 2 отобран с тем же tie-break, что и batch 1 (по возрастанию `sourceGroupId`/`canonicalProductId` при полном совпадении трёх метрик) — новый manufacturer-tier tie-break (см. ниже) вступает в силу начиная с batch 3 и не пересчитывает уже отобранные batch 1–2.

Покрытые `canonicalProductId` batch 2:

`daily-hookah-slivochnyi-krem`, `deus-skittles`, `overdose-masala-tea`, `urban-soul-berry-marmalade`, `blackburn-shock-raspberry`, `overdose-jelly-grape`, `blackburn-green-tea`, `jam-arbuznyi-rondo`, `jam-spelaya-marakuiya`, `hook-limon-laim`, `blackburn-almond-pear`, `overdose-samarkand-melon`, `husky-kiwano`, `overdose-apple-juicy`, `sapphire-crown-bitter-cherry`.

## Данные и evidence

- Суммарно (batch 1 + batch 2): 30 продуктов, 50 заполненных измерений из 120 возможных, 103 evidence-записей.
- Только batch 2: 15 продуктов, 22 заполненных измерения из 60 возможных.
- Три продукта batch 2 (`jam-spelaya-marakuiya`, `blackburn-almond-pear`, `husky-kiwano`) не получили ни одного заполненного измерения — независимое вкусовое описание не найдено даже через агрегированный поиск; `dimensions: {}`, `overallConfidence: LOW`, `dominantNoteIds` заполнены по подтверждённому названию продукта (аналогично `urban-soul-pineapple` из batch 1).
- Один случай прямого противоречия источников зафиксирован явно: `overdose-jelly-grape` — одни источники описывают «насыщенное сладкое послевкусие», другие — «минимальная сладость, хорошо сбалансирован»; выбрано среднее значение с `LOW` confidence и evidence, документирующим оба источника и сам факт расхождения.
- Один случай уточнения при риске ошибочного сопоставления: для `hook-limon-laim` изначальный веб-поиск указывал на другой товар бренда Hook («Цитрусовый»/`tsitrusovyy`); отдельным запросом подтверждена именно позиция «Лимон Лайм» в каталоге HTReviews прежде, чем она была использована как evidence — по аналогии с общим принципом проекта «никаких выводов по похожести названия».
- `HIGH` confidence не использован ни разу (Confidence breakdown только по batch 2: `LOW` — 8, `MEDIUM` — 7, `HIGH` — 0).

## Manufacturer priority tier — новый явный tie-break (для batch 3+)

По отдельному запросу зафиксирован явный, кодифицированный (не разовый ручной) вторичный tie-break очереди приоритизации, вступающий в силу начиная с batch 3:

- Первичный критерий не меняется: `verifiedMixCount → componentOccurrenceCount → occurrenceCount`, по убыванию.
- При полном совпадении всех трёх метрик предпочтение отдаётся производителю с более богатыми официальными/независимыми источниками:
  - Tier 1 (высший приоритет): `Darkside`, `Chabacco`, `MustHave`, `Sapphire Crown`, `Element`;
  - Tier 2: `Sebero`, `Overdose`, `Husky`, `Brusko`, `BlackBurn`;
  - Tier 3 (низший приоритет, не исключается): все остальные производители.
- Финальный tie-break при равенстве всего перечисленного — по возрастанию `canonicalProductId`.
- Реализация: `src/lib/product-flavor-profile/priority-queue.ts` (`getManufacturerPriorityTier`, `comparePriorityQueueCandidates`, `sortByPriorityQueue`), покрыта `priority-queue.test.ts` (17 тестов). Сопоставление manufacturer → tier — точное нормализованное совпадение (trim + lowercase), без fuzzy matching, без alias-резолюции.
- Batch 1 и batch 2 не пересчитываются задним числом: они отобраны до появления этого правила и используют исходный tie-break по `sourceGroupId`/`canonicalProductId`.

## Рефакторинг структуры (без изменения публичного контракта)

Данные batch 1 и batch 2 вынесены в отдельные версионированные файлы `batch-1.ts` / `batch-2.ts` (по образцу `p0-decisions-batch-N.ts` в `tobacco-identity-decisions`), общие evidence-хелперы — в `evidence-helpers.ts`. `registry.ts` теперь только объединяет батчи и валидирует результат. Публичный API (`index.ts`) не изменился; дополнительно экспортированы `PRODUCT_FLAVOR_PROFILES_BATCH_1`, `PRODUCT_FLAVOR_PROFILES_BATCH_2` и новый priority-queue API.

## Ограничения

- Покрыты 30 из 86 `RESOLVED` продуктов; остальные 56 — предмет следующих батчей.
- Registry по-прежнему не подключён к `calculateMixAnalysis`, Compatibility/Recommendation Engine, canonical mix scoring или UI.
- Часть evidence получена через агрегированный веб-поиск без прямой проверки исходной страницы (отмечено `LOW` confidence).
