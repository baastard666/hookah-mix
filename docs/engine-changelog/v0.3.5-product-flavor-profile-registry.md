# v0.3.5 — Product Flavor Profile Registry

## Цель

Создан независимый read-only справочник числовых вкусовых характеристик (`sweetness`, `sourness`, `freshness`, `richness`) для уже разрешённых (`RESOLVED`) канонических продуктов — по образцу `tobacco-product-profile-registry` (ADR-007) и с evidence/confidence по ADR-003. Итерация устраняет исходную проблему, зафиксированную в v0.3.3 (все effective-профили падали на нейтральный fallback), но **не подключает** новый registry к `calculateMixAnalysis`, scoring или UI — это отдельная будущая итерация.

## Область охвата

Из 86 `RESOLVED` решений Tobacco Identity Decision Registry заполнен первый приоритетный батч — 15 продуктов, отобранных той же очередью, что и P0/P1 identity decisions: сортировка по `verifiedMixCount` → `componentOccurrenceCount` → `occurrenceCount` по убыванию (с детерминированным добавочным тай-брейком по возрастанию `sourceGroupId`, так как в текущем 37‑миксовом workbook эти три метрики совпадают у большинства продуктов).

Покрытые `canonicalProductId`:

`sapphire-crown-dried-plum`, `sapphire-crown-go-bananas`, `musthave-sorbetto`, `blackburn-na-rasslabone`, `blackburn-klyukvennyi-mors`, `blackburn-na-chille`, `musthave-blackberry`, `musthave-sour-berries`, `blackburn-tic-tac`, `blackburn-ice-baby`, `musthave-sour-tropic`, `musthave-sour-citrus`, `sapphire-crown-pineapple-fanta`, `urban-soul-pineapple`, `nash-white-line-karamel-tsitrus`.

## Данные и evidence

- 28 заполненных измерений из 60 возможных (15 продуктов × 4 измерения); остальные оставлены незаполненными за отсутствием независимого источника — численные значения не изобретались.
- 55 evidence-записей: официальные страницы производителя (MustHave), независимые агрегаторы обзоров (HTReviews) и описания ритейлеров, плюс обязательная `EDITORIAL_ASSESSMENT`-запись при каждом численном значении, документирующая, что перевод текстового описания в шкалу 0–10 — редакционная интерпретация, а не независимое измерение.
- Confidence breakdown по продуктам: `LOW` — 6, `MEDIUM` — 9, `HIGH` — 0. `HIGH` не использован ни разу: вкусовые измерения субъективны по своей природе и не являются прямым однозначным заявлением производителя о составе, поэтому потолок confidence — `MEDIUM` (ADR-003 применён с учётом этого ограничения).
- Два продукта (`blackburn-klyukvennyi-mors`, `nash-white-line-karamel-tsitrus`) имеют только одно измерение с `LOW` confidence из-за скудности независимых источников; один продукт (`urban-soul-pineapple`) не имеет ни одного заполненного измерения — независимое вкусовое описание не найдено, `dimensions: {}`, `overallConfidence: LOW`.

## Модель и API

Новый модуль `src/lib/product-flavor-profile/`: `types.ts`, `constants.ts`, `errors.ts`, `validation.ts`, `registry.ts`, `queries.ts`, `public-mapper.ts`, `index.ts`. Registry — глубоко замороженный массив `ProductFlavorProfile`, построение которого выбрасывает типизированную `ProductFlavorProfileError`, если хотя бы один `canonicalProductId` не найден или не `RESOLVED` в Tobacco Identity Decision Registry, если численное значение вне диапазона 0–10, если `overallConfidence` превышает минимальный confidence среди заполненных измерений, либо если `dominantNoteIds` ссылается на несуществующую категорию Flavor Knowledge Layer.

Публичный API: `getProductFlavorProfile`, `listProductFlavorProfiles`, `hasProductFlavorProfile`, `mapProductFlavorProfileToPublic`. Raw registry не экспортируется из `index.ts`. Публичный mapper исключает `reference`-URL из evidence, оставляя только `type`, `title`, `checkedAt`.

## Ограничения

- Покрыты 15 из 86 `RESOLVED` продуктов; остальные 71 — предмет следующих батчей той же приоритетной очереди.
- Registry не подключён к `calculateMixAnalysis`, Compatibility/Recommendation Engine, canonical mix scoring или UI.
- Flavor Knowledge Layer не расширен новыми категориями; `dominantNoteIds` используют только уже существующий список (`BERRY`, `FRUIT`, `TROPICAL`, `CITRUS`, `SOUR`, `DESSERT`, `CREAMY`, `MINT`, `CANDY`, `COOLING`, `BEVERAGE` и т.д.).
- Часть evidence получена через агрегированный веб-поиск без прямой проверки исходной страницы (отмечено `LOW` confidence в соответствующих записях); при появлении более сильных источников оценки следует пересмотреть.
