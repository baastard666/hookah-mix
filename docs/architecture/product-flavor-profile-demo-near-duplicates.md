# Review-список: возможные смысловые почти-дубли Product Flavor Profile Registry ↔ demo `Flavor`

## Назначение

ADR-016 запрещает автоматическое объединение продуктов Product Flavor Profile Registry с существующими demo-строками Prisma `Flavor`, когда они технически различны (разный `slug`/название), но могут оказаться одним и тем же физическим товаром. Вместо автоматики — этот список для будущего ручного identity-decision, по аналогии с P0/P1-процессом Tobacco Identity Decision Registry (`reports/unresolved-identity-report.json` → `p0-decisions-batch-N.ts`). Пункты не решаются молча внутри будущего импортёра; каждый требует отдельного явного решения человека, прежде чем что-либо менять в данных.

Это read-only список для будущей работы, а не сама реализация решения — ни объединение, ни разделение здесь не выполняется.

## Как проверялся список

Сопоставлены все 8 demo-строк `prisma/seed.ts` (кроме `Test Kitchen`, у которого `catalogEntryType: TEST` и который не является реальным продуктом ни в каком смысле) с 86 продуктами Product Flavor Profile Registry по 5 пересекающимся брендам (`Overdose`, `Element`, `MustHave`, `BlackBurn`, `Daily Hookah` — 26 продуктов из 86). Для каждой demo-строки проверено, есть ли среди продуктов registry того же бренда концептуально похожий вкус (по названию/составу), не совпадающий технически (`slug`/название).

## Найденные пары

### 1. `daily-hookah-slivochnyi-krem` (registry) ↔ `Daily Hookah / Сливки` (demo, `slug: cream`)

- **Registry:** `canonicalProductId: daily-hookah-slivochnyi-krem`, бренд `Daily Hookah`, название по решению Tobacco Identity Decision Registry — «Сливочный крем».
- **Demo:** бренд `Daily Hookah`, название «Сливки», `slug: cream`, синтетические значения (`profileSource: MANUAL`, без evidence).
- **Почему это подозрительная пара:** оба — единственный вкус бренда `Daily Hookah` в своей коллекции, оба явно про сливочный/кремовый вкус, разница только в формулировке названия («Сливки» vs «Сливочный крем»). Ничего в имеющихся данных не подтверждает и не опровергает, что это один и тот же физический товар — только его же под чуть разным названием на разных этапах составления каталога.
- **Статус:** не решено. Не объединять и не удалять автоматически ни при каком будущем импорте.
- **Что нужно для решения:** сверка с оригинальным каталогом производителя `Daily Hookah` (официальный сайт/прайс-лист) — существует ли отдельно вкус «Сливки» и отдельно «Сливочный крем», или это одно и то же название, попавшее в источники в двух формулировках.

## Пары, проверенные и отклонённые (не почти-дубли)

Для полноты — остальные 4 пересекающихся бренда проверены и явных кандидатов на смысловое совпадение не дали:

- **Overdose** — demo `Coffee` (`slug: coffee`) технически совпадает (не почти-дубль, а точная коллизия) с `overdose-coffee`; см. ADR-016 п. 2 (evidence побеждает при апсерте, это не предмет этого списка). Остальные 5 продуктов registry этого бренда (`masala-tea`, `jelly-grape`, `samarkand-melon`, `apple-juicy`, `strawberry`) концептуально не пересекаются с demo `Coffee`.
- **Element** — demo `Мята` (Mint) не пересекается по смыслу ни с `element-air-milky-mouse`, ни с `element-earth-wildberry-mors`.
- **MustHave** — demo `Манго` (Mango) не пересекается по смыслу ни с одним из 9 продуктов registry этого бренда (`sorbetto`, `blackberry`, `sour-berries`, `sour-tropic`, `sour-citrus`, `maple-pecan`, `pineapple-rings`, `vanilla-cream`, `apple-drops`).
- **BlackBurn** — demo `Ваниль` (Vanilla) не пересекается по смыслу ни с одним из 8 продуктов registry этого бренда (`na-rasslabone`, `klyukvennyi-mors`, `na-chille`, `tic-tac`, `ice-baby`, `shock-raspberry`, `green-tea`, `almond-pear`).

## Обновление списка

Список пополняется по мере появления новых пересечений в будущих итерациях registry (новые батчи, новые demo-данные) — не переписывается и не «закрывается» автоматическим слиянием. Каждая новая подозрительная пара добавляется отдельным пунктом с тем же набором полей (registry-сторона, demo-сторона, обоснование подозрения, статус, что нужно для решения).
