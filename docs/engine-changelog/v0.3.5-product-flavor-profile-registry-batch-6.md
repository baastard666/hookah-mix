# v0.3.5 — Product Flavor Profile Registry, batch 6 (финальный)

## Цель

Шестой, последний батч. Покрытие расширено с 75 до **86 из 86** `RESOLVED` продуктов — Product Flavor Profile Registry теперь охватывает каждый `RESOLVED`-продукт Tobacco Identity Decision Registry без исключений. Это завершает первую итерацию v0.3.5 в части наполнения данными.

## Очередь приоритизации — фактический порядок

Ранги 1–11 среди последних 11 оставшихся `RESOLVED`-продуктов (вычислено `sortByPriorityQueue`):

1. `urban-soul-strawberry` (Urban Soul, Tier 3, `occurrenceCount = 2` — последний продукт с этой метрикой)
2. `musthave-apple-drops` (MustHave, Tier 1)
3. `sapphire-crown-pumpkin-raf` (Sapphire Crown, Tier 1)
4. `sapphire-crown-sunny-peach` (Sapphire Crown, Tier 1)
5. `sapphire-crown-yuzu-honey` (Sapphire Crown, Tier 1)
6. `deus-perfume-black-afgano` (Deus, Tier 3)
7. `element-earth-wildberry-mors` (Element, Tier 3)
8. `sarma-360-dzhin` (Sarma, Tier 3)
9. `sarma-360-gornaya-lavanda` (Sarma, Tier 3)
10. `sarma-360-light-shampanskoe` (Sarma, Tier 3)
11. `sarma-360-persik` (Sarma, Tier 3)

Ранги 2–5 (`MustHave`/`Sapphire Crown`, формально Tier 1) идут раньше рангов 6–11 (Tier 3), несмотря на одинаковый `occurrenceCount = 1` — это первый случай в этом проекте, где tier-tie-break реально определяет порядок внутри группы с равными primary-метриками, а не просто подтверждает уже очевидный порядок. Ранг 1 (`urban-soul-strawberry`) идёт впереди всех благодаря более высокому `occurrenceCount = 2`, который доминирует над tier независимо от того, что сам Urban Soul — Tier 3.

Очередь пуста после этих 11 продуктов: `TOBACCO_IDENTITY_DECISION_REGISTRY.getByStatus("RESOLVED")` и `PRODUCT_FLAVOR_PROFILE_REGISTRY` теперь совпадают по составу `canonicalProductId` один в один — это проверено отдельной сверкой в `scripts/verify-product-flavor-profile.ts`.

## Данные и evidence

- Заполнено 28 новых измерений, доведя суммарный итог по 86 продуктам до 271 заполненного измерения из 602 возможных (86 × 7) и 546 evidence-записей.
- Только batch 6: `overallConfidence` — `MEDIUM` у 9 продуктов, `LOW` у 2 (`sapphire-crown-sunny-peach`, `element-earth-wildberry-mors` — в обоих случаях единственная причина `LOW` — крепость перенесена с уровня бренда/линейки, а не подтверждена для конкретного вкуса).
- Кросс-брендовое/кросс-товарное смешение явно исключено дважды: для `urban-soul-strawberry` — отзывы на смесь «Strawberry Kiwi Grapefruit» (другой, многокомпонентный вкус) намеренно не использованы; для `sarma-360-persik` — розничное упоминание варианта «Персик-Молоко» намеренно не использовано, так как у «Персик» есть собственная страница на HTReviews с отдельным описанием.
- Прямое указание источника, что вкус НЕ сочный, использовано как основание не заполнять `juiciness`: список вкусов линейки «Крепкая Сарма 360» описывает «Персик» как «фруктовый, а не сочный профиль» — явно задокументировано в evidence, чтобы не выглядеть как пропуск.
- `juiciness` заполнен только у `element-earth-wildberry-mors`, где официальное описание малины в составе микса прямо использует слово «juiciness» (сочность) — единственное совпадение в этом батче.
- `HIGH` confidence не использован ни разу.

- `scripts/verify-product-flavor-profile.ts` дополнен финальной сверкой: множество `canonicalProductId` в registry теперь сравнивается напрямую (`assert.deepEqual`) с полным списком `RESOLVED`-решений Tobacco Identity Decision Registry — подтверждает, что не пропущен и не выдуман ни один продукт.
- Модуль `product-flavor-profile`: **56/56 passed** (было 55/55 после batch 5).
- Полный Vitest: **962/962 passed, 29 files** (было 961/29 после batch 5).
- `tsc --noEmit`: без ошибок. `eslint .`: без замечаний.
- `verify:product-flavor-profile`: 86 продуктов, 271 заполненное измерение, 546 evidence, confidence LOW/MEDIUM/HIGH = 47/39/0, ноль validation issues, множество canonicalProductId совпадает с полным списком RESOLVED — все числа сверены вручную по каждому из 11 новых продуктов и совпали в точности.
- Prisma schema, миграции, существующие engines и `TobaccoIdentityDecision`-записи не изменены.

## Итог по всей регистратуре v0.3.5

- **86 из 86** `RESOLVED` продуктов покрыты; ни один продукт не пропущен, ни одно значение не выдумано при отсутствии источника.
- Целевая модель — 7 измерений (`sweetness`, `sourness`, `freshness`, `intensity`, `strength`, `heatResistance`, `juiciness`) согласно ADR-014; 271 из 602 возможных значений заполнено (45%) — доля объясняется тем, что для многих продуктов реального независимого источника по части измерений просто не существует, а не пропуском работы.
- Для линейки Husky по-прежнему нет ни одного значения `heatResistance` ни для одного продукта во всех батчах — задокументированное, а не случайное ограничение.
- Registry по-прежнему не подключён к `calculateMixAnalysis`, scoring или UI — это отдельная будущая итерация, требующая собственного решения о приоритизации.
- Flavor Knowledge Layer не расширен новыми категориями; Prisma schema, миграции и Tobacco Identity Decision Registry не изменены на всём протяжении v0.3.5.
