# ADR-007: отдельный Tobacco Product Profile Registry

## Context

Текущие движки анализируют вкус и пропорции. При этом производители и линейки могут различаться по крепости, жаростойкости и типу листа. Эти технические свойства не являются вкусовой таксономией и не должны скрыто менять действующие формулы.

## Decision

Создать отдельный read-only Tobacco Product Profile Registry с уровнями Manufacturer → Product Line → future Product, явным наследованием, evidence, confidence и ограниченным alias matching. Не смешивать его с Flavor Knowledge Layer, `FlavorProfile`, Prisma или текущими движками. В v0.2.7 registry не подключать к анализу и UI.

## Consequences

- будущий Tobacco Compatibility Engine сможет получать объяснимые технические данные через публичный API;
- текущие результаты анализа остаются неизменными;
- происхождение значений и неопределённость видимы;
- качество будущего результата будет ограничено полнотой и качеством evidence;
- обновление справочника требует проверки источников и тестов.

## Alternatives considered

- хранить свойства прямо в Compatibility Engine — смешивает данные и правила;
- добавить их в Flavor Knowledge Layer — смешивает вкусовые и технические понятия;
- хранить одно значение на производителя — теряет различия линеек;
- сразу изменить Prisma schema — преждевременно связывает экспериментальный справочник с БД.
