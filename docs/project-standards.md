# Project standards

- Разделять engine, application/orchestration и presentation layers. UI не содержит бизнес-формул.
- Использовать только публичные `index.ts`; не дублировать типы и правила.
- Расчёты детерминированы, без скрытых мутаций, времени, случайности и внешнего состояния.
- TypeScript strict, без необоснованного `any`; функции и ошибки типизированы.
- Новое поведение покрывается unit-тестами; публичные конвейеры — verify-скриптами.
- Архитектурный модуль документируется в `docs/architecture`; значимое решение — ADR с очередным номером.
- Изменения движков записываются в `docs/engine-changelog`; изменение планов — в roadmap без вымышленных сроков.
- Итоговый отчёт содержит Git, файлы, архитектуру, проверки, подтверждения и реальные ограничения.

## Definition of Done

Код завершён; тесты, typecheck, lint, production build и профильные verify проходят; architecture docs и необходимый ADR обновлены; engine changelog и при необходимости roadmap актуальны; Git-ветка опубликована, рабочая директория чистая.
