# v0.3.3 — Canonical Mix Scoring Integration

## Цель

Authoritative каталог v0.3.2 подключён к реальному расчёту и рекомендациям без изменения 96 identity decisions. Каждый компонент сначала проходит exact canonical resolution и получает effective profile, после чего существующие Mix Profile, Compatibility и Recommendation Engine работают с нормализованными компонентами.

## Resolution pipeline

```text
Prisma/workbook source component
  -> authoritative exact decision / canonical ID / constrained exact alias
  -> RESOLVED | MANUFACTURER_ONLY | AMBIGUOUS | UNRESOLVED
  -> effective profile with provenance
  -> aggregate equal RESOLVED canonicalProductId
  -> existing analysis engines
  -> predicted quality, confidence and data quality
```

- `RESOLVED` использует canonical product и сохраняет raw identity/source ID внутри.
- `MANUFACTURER_ONLY` не получает продукт или line; допустимы только source/fallback profile.
- `AMBIGUOUS` сохраняет неоднозначность и не выбирает Classic/Black или другой кандидат.
- `UNRESOLVED` не получает guessed manufacturer/product.

Fuzzy matching, Levenshtein и разрешение по вкусовому слову отсутствуют.

## Effective profile priority

Приоритет: user smoke → internal test → canonical product profile → external aggregate → catalog/preliminary technical profile → source profile → neutral fallback. Выбор выполняется по каждому полю с provenance и reliability; пользовательские фактические данные не затираются агрегатами. Manufacturer-only technical data не выдаётся за product profile.

## Duplicate handling

Два raw-компонента объединяются только при одном `RESOLVED canonicalProductId`. Их доли суммируются, source IDs сохраняются, создаётся `DUPLICATE_CANONICAL_COMPONENT`. Равные названия у разных производителей или линеек не объединяются. Тест exact `Tic Tac` + alias `Tik Tak` подтверждает отсутствие двойного влияния на score.

## Scoring model

Централизованные веса: compatibility 25%, proportions 20%, component quality 20%, balance 15%, risks 10%, confirmations 10%. Итог разделён на:

- `predictedQualityScore` — прогноз 0–10;
- `predictionConfidence` — уверенность с weighted identity/profile coverage;
- `dataQuality` — полнота и надёжность входа;
- `verifiedSmokeScore` — отдельная реальная оценка, только если существует.

Отсутствие canonical identity снижает confidence/data quality пропорционально доле, но не штрафует predicted quality автоматически. Количество отзывов не подменяет качество смеси.

## Интеграция

- `calculateMixAnalysis` нормализует компоненты перед profile/compatibility/recommendations;
- Prisma adapter передаёт persisted canonical ID и source profile reliability;
- POST `/api/mixes` использует новый analysis pipeline и возвращает public-safe canonical components и scoring summary, сохраняя прежний `id`;
- `/result/[id]` маркирует число как прогноз, показывает confidence/data quality и использует canonical IDs в recommendation mapping;
- старый heat analysis сохранён как compatibility layer.

## Corrective logic and recommendation patch

Ручная проверка `Test Kitchen Cola 80% + Element Мята 20%` выявила смешение нескольких независимых состояний. Patch разделяет наличие товара в Prisma-каталоге, authoritative canonical resolution и надёжность вкусового профиля. Для найденного товара без exact identity UI больше не пишет просто «Не распознан»: catalog, canonical и profile status показаны отдельно, без enum и внутренних ID.

- Значимые dominant-ноты компонентов с долей от 15% участвуют в публичном названии. Сценарий выводится как «Кола + мята»; `mint` не превращается в `spice`, а подтверждённая secondary-нота `spice` остаётся фоновой и локализуется.
- `recommendedCatalogRole` не подменяет `actualMixRole`: Cola 80% — основа и доминирующий компонент; Мята 20% — поддержка и холодящий компонент.
- Публичное поле `risks` называется «Устойчивость к рискам», поскольку 10 означает отсутствие существенных рисков. Penalty применяется по детерминированным причинным группам; связанные `intensity.overdominant` и `proportion.bright-large.*` не штрафуют и не отображаются дважды.
- Recommendation Engine выбирает ближайшую границу диапазона, а не midpoint. Для 80% первичный шаг равен 75%, то есть 5 процентным пунктам.
- Candidate проходит повторный полный расчёт profile → compatibility → scoring → risks. Вариант показывается только при снижении целевого риска, отсутствии нового HIGH-риска, сохранении score/profile balance и сумме 100%.
- При preliminary/fallback profile значения маркируются как ориентировочные и округляются на presentation-слое; raw score не меняется. `componentQuality` публично переименован в «Потенциал компонентов».
- Сохранённые чаша, угли и прогрев обозначены как «Параметры исходного рецепта».
- Добавлена локализация `cola`, `mint`, `cooling`, `herbal`, `spice`; реальные brand/product names не переводятся.
- Result UI получил единый блок надёжности, deterministic summary, компактные statuses, current/proposed comparison и переходы в builder с текущими или принятыми пропорциями. Новый Mix создаётся только после явного запуска анализа.
- Badges используют `inline-flex` и `white-space: nowrap`; desktop/mobile проверены без horizontal overflow.
